# GOAR – Recipes Android App

Android app for managing recipes, ingredients and shopping lists.
Java, Material Design 3, minSdk 30.

## Project structure

```
com.example.goar
├── ui                      UI layer
│   ├── activities          MainActivity (toolbar, bottom navigation, drawer, NavHostFragment)
│   ├── fragments/<feature> one package per feature: Fragment + its ViewModel
│   └── adapters            RecyclerView adapters
└── data                    Data layer
    ├── model               shared entities (Recipe, Ingredient, User...)
    └── repository          data access (MockData for now, database later)
```

Navigation graph: `res/navigation/base_navigation.xml`
Menus: `res/menu/bottom_nav_menu.xml`, `drawer_menu.xml`, `toolbar_menu.xml`
Theme and colors: `res/values/themes.xml`, `res/values/colors.xml`, `res/values-night/colors.xml`

## Git workflow

- `main` always builds and runs.
- Everyone works on their own branch: `student1/<feature>`, `student2/<feature>`, `student3/<feature>`.
- Before starting work: `git checkout main` and `git pull`, then create or update your branch.
- When a feature is done, merge it into `main` through a pull request.
- Do not commit `.idea/gradle.xml` or other IDE files that change on every machine.

## Rules

- Do not change other students' packages.
- Keep screen state (search text, filters, sorting) in the fragment's ViewModel with LiveData, not in the fragment, so it survives navigation and screen rotation.
- Use ViewBinding instead of `findViewById`.
- All UI text goes to `strings.xml`, in English.
- Use theme colors (`?attr/colorPrimary`, `?attr/colorSurface`...) instead of hardcoded colors.
- To add a screen: create the fragment in your package and add it to `base_navigation.xml`.

## Mock data

- `MockData` holds shared test data (users, types, categories, allergens, ingredients, recipes).
- `SessionManager` holds the current user. Until login is implemented (Student 1), the user comes from `MockData`.
- `MockData.CURRENT_USER_IS_ADMIN`: `true` shows the app as admin (Admin panel visible), `false` as a regular user.
- Logout is a placeholder until Student 1 implements authentication.

## Firestore structure

Shared agreement for the database. Change only after the team agrees.

- Document IDs are generated by Firestore (String). A user's ID is their Firebase Auth `uid`.
- Enums are stored as text (`"BAKING"`, `"NEW"`).
- Dates are stored as Firestore `Timestamp`.
- References store the ID, plus the name where it is needed for display (`authorId`, `authorUsername`).

| Collection | Fields | Owner |
|---|---|---|
| `users/{uid}` | username, email, profileImageUrl, region, bio, role, recipeCount | Student 1 |
| `users/{uid}/favorites/{recipeId}` | addedAt | Student 1 |
| `users/{uid}/recentlyViewed/{recipeId}` | viewedAt | Student 3 |
| `users/{uid}/recentlyCooked/{recipeId}` | cookedAt | Student 1 |
| `users/{uid}/pantry/{id}` | ingredientId (optional), ingredientName, brand, quantity, unit, expiryDate, barcode | Student 2 |
| `users/{uid}/shoppingLists/{id}` | name, createdAt, plannedDateTime, permanent, archived, items[] | Student 2 |
| `users/{uid}/notifications/{id}` | title, message, type, relatedId, createdAt, read | Student 3 |
| `recipes/{id}` | name, authorId, authorUsername, authorRegion, mealTypeId, dishTypeId, dietTypeId, servings, totalTimeMinutes, mainImageUrl, additionalImageUrls, videoUrl, ingredients[], steps[], origin {country, region, city}, story, createdAt, averageRating, ratingCount, allergenIds[], ingredientIds[], preparationTypes[], originalRecipeId, originalRecipeName, modificationNote | Student 1 |
| `recipes/{id}/ratings/{userId}` | recipeId, value, createdAt, updatedAt | Student 2 |
| `recipes/{id}/comments/{id}` | authorId, authorUsername, text, imageUrls, createdAt, editedAt, parentCommentId | Student 2 |
| `reports/{id}` | targetType, targetId, recipeId, commentId, photoUrl, reason, reporterId, reporterUsername, createdAt, status, rejectionReason | Student 2 |
| `ingredients/{id}` | name, categoryId, defaultUnit, quantityOptional, type, allergenIds[] | Student 3 |
| `mealTypes`, `dishTypes`, `dietTypes`, `ingredientCategories`, `allergens` | name | Student 3 |
| `categoryRequests/{id}` | ingredientName, proposedName, explanation, requesterId, status, adminResponse | Student 3 |

List items:
- `recipes.ingredients[]`: ingredientId, ingredientName, type, quantity, unit
- `recipes.steps[]`: order, title, description, imageUrls, preparationType, durationMinutes
- `shoppingLists.items[]`: ingredientId, ingredientName, type, quantity, unit, purchased

Notes:
- `allergenIds`, `ingredientIds` and `preparationTypes` in `recipes` are filled when a recipe is saved, so search can filter by them.
- `averageRating` and `ratingCount` are updated when a rating changes.
- One rating per user per recipe: the rating document ID is the user's `uid`.
- A report can be withdrawn (deleted) only while its status is `NEW`.
